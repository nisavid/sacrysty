## Evidence baseline

**Observed in the frozen source.** The Go module declares Go 1.23.5, age at pseudo-version v1.2.1-0.20240926110859-2214a556f604, and go-libfido2 at pseudo-version v1.5.4-0.20250104233141-2534349bd685; go.sum supplies module checksums ([module declarations](https://github.com/FiloSottile/typage/blob/38b8b10cb22409de0eaa8a617a01f16dc2e3f9f4/go.mod#L1-L15)). Credential creation requires exactly one discovered FIDO2 device, requests the HMAC-secret extension and user verification, and records a versioned credential ID, relying-party ID, and “usb” transport. Assertion first probes for a matching credential, requests UV, and asks for a PIN only after ErrPinRequired. It rejects a missing HMAC-secret result. These are code-path facts, not observations from a real authenticator ([implementation](https://github.com/FiloSottile/typage/blob/38b8b10cb22409de0eaa8a617a01f16dc2e3f9f4/fido2prf/fido2prf.go)).

The command supports credential generation and age plugin identity and identity-as-recipient handlers. Its TODOs mention resident-credential listing and possible non-UV support; neither is an implemented or committed support claim in this snapshot ([entry point](https://github.com/FiloSottile/typage/blob/38b8b10cb22409de0eaa8a617a01f16dc2e3f9f4/fido2prf/cmd/age-plugin-fido2prf/main.go)).
